# 레슨 06 — 교사 가이드

## 학습 목표 (교사용)

- 브라우저 자동화가 필요한 상황을 구분한다.
- locator, fill, click, text_content 흐름을 이해한다.
- 폼 입력과 버튼 클릭 결과를 검증한다.
- 여러 CSV 케이스로 반복 QA를 수행한다.
- 자동화 로그를 CSV로 저장한다.

## 2시간 수업 흐름

| 시간 | 운영 | 확인 포인트 |
|---:|---|---|
| 0-15분 | fixture 구조 읽기 | 상태·폼·selector 기준 확인 |
| 15-45분 | 강의 예제 실행 | 환경 셀과 helper 동작 확인 |
| 45-85분 | 문제 1~10 풀이 | 상태 변화와 반복 처리 확인 |
| 85-110분 | 문제 11~15 풀이 | 로그와 CSV 저장 확인 |
| 110-120분 | 최종 미션 정리 | 산출물과 요약 문장 검수 |

## 사전 준비

- 코랩 링크가 Kevin-innovation/jupyter-lecture 저장소를 가리키는지 확인한다.
- data 폴더의 fixture 파일을 먼저 열어 학생이 볼 태그와 상태 속성을 확인한다.
- 실제 사이트를 바로 요청하지 말고 합성 fixture로 구조를 읽게 한다.

## 질문 유도

- 상태가 코드 어디에 저장되는가?
- 화면 문구와 안정 selector 중 어느 쪽이 유지보수에 좋은가?
- 클릭 또는 입력 이후 어떤 값이 바뀌었는가?
- 이 자동화를 다음 주에도 실행한다면 어떤 로그가 필요한가?

## 채점 기준

15문제 중 12문제 이상 통과를 기본 완료로 본다. 최종 미션은 산출물 파일과 3문장 요약이 함께 있어야 완료 처리한다. 정답 코드와 다른 방식이어도 구조, 상태 변화, 출력 형태가 맞으면 인정한다.

## 자주 발생하는 오류

| 오류 | 원인 | 지도 방법 |
|---|---|---|
| 값이 비어 있음 | 입력 전 결과를 읽음 | fill/click 순서를 확인한다 |
| selector 오류 | 문구 기반 선택 | id, data-testid, role 기준으로 바꾼다 |
| wait 실패 | 아직 표시되지 않은 요소 읽음 | 조건 확인 후 wait를 사용한다 |
| 로그 누락 | 결과만 출력 | action/result를 리스트로 남기게 한다 |

## 확장 과제

결과를 CSV와 JSON 두 가지로 저장하거나, 처리 로그를 별도 리스트로 남기게 한다. 빠른 학생은 함수 분리와 오류 처리까지 진행한다.

## 운영 세부 가이드

학생에게 “코드가 돌아간다”와 “자동화가 검증된다”는 서로 다른 말이라고 설명한다. 결과 문자열이 한 번 출력되어도 selector가 불안정하거나 상태 확인이 빠져 있으면 운영 자동화로 보기 어렵다. 각 문제를 채점할 때는 코드 줄 수보다 절차가 남아 있는지 본다.

빠른 학생은 Playwright 문법과 비교하게 한다. MiniPage의 `locator`는 Playwright의 locator 개념, `fill`은 입력, `click`은 이벤트, `wait_for_selector`는 조건 대기, `log`는 trace나 test report의 축약 모델이다. 느린 학생은 HTML 파일을 먼저 열고 id, data-testid, data-target만 색연필로 표시하게 하면 selector 이해가 빨라진다.

## 피드백 문장 예시

- selector는 맞지만 클릭 후 상태 확인이 빠져 있어서 자동화 성공을 판단하기 어렵다.
- 반복 케이스마다 새 page를 만든 점은 좋다. 이제 실패 케이스를 따로 모으면 더 운영형 코드가 된다.
- data-testid를 사용한 점은 안정적이다. 실제 프로젝트에서도 테스트용 속성을 요청할 수 있다.
- CSV 저장까지 했지만 header가 없으면 나중에 읽기 어렵다. DictWriter의 writeheader를 확인하자.
- wait 조건을 명확히 잡은 점이 좋다. 무작정 시간을 늘리는 방식보다 유지보수에 유리하다.

## 다음 회차 연결

다음 회차에서는 페이지 이동과 더 복잡한 수집 흐름을 다루게 된다. 6강에서 selector, 상태, wait, log를 제대로 잡아두면 다음 레슨에서 브라우저 자동화 코드가 갑자기 길어져도 구조를 유지할 수 있다. 수업 마지막 5분에는 학생에게 본인이 사용한 selector 3개와 그 selector를 고른 이유를 말하게 한다.

## 문제 풀이 진행 방식

1~5번은 강사가 함께 풀어도 좋다. 이 구간에서 MiniPage의 역할, locator의 의미, fill과 click의 차이를 잡아야 뒤 문제가 수월하다. 6~8번은 학생이 직접 풀게 두고, 막히면 data-testid와 CSV 헤더를 먼저 확인하게 한다. 9~11번은 상태 전환 문제이므로 클릭 전후 같은 요소를 비교하는지 확인한다. 12~15번은 wait, log, 저장 산출물을 다루므로 결과만 맞아도 저장 파일이 없으면 다시 보게 한다.

## 수업 중 금지할 습관

- selector를 화면 문구나 현재 순번에만 의존하는 습관
- 입력 후 value를 확인하지 않고 바로 클릭하는 습관
- 클릭 결과를 확인하지 않고 다음 단계로 넘어가는 습관
- 반복 케이스에서 같은 page 객체를 계속 재사용하는 습관
- 로그에 비밀번호나 개인 식별 정보를 남기는 습관
- 파일 저장 없이 화면 출력만 제출하는 습관

## 빠른 학생 확장 과제

빠른 학생에게는 QA row에 `case_no`, `error`, `duration` 필드를 추가하게 한다. try/except로 실패 케이스를 잡고, 실패해도 전체 반복이 중단되지 않게 만들면 실제 운영 자동화에 가까워진다. 또 CSV 저장 후 JSON 요약을 별도로 만들게 하면 데이터 분석 레슨과도 연결된다.

## 느린 학생 보조 과제

느린 학생은 코드를 늘리기보다 HTML 구조를 먼저 읽게 한다. `form_page.html`에서 id 세 개, button id 하나, result id 하나를 찾게 하고, 그 값을 표로 적게 한다. 그 다음 문제 코드의 `____`에 표의 값을 하나씩 넣게 하면 selector 오류가 줄어든다. Todo와 탭도 같은 방식으로 data-target과 panel id를 짝지어 적게 한다.

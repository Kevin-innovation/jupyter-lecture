# 레슨 05 — 교사 가이드

## 수업 목표

- 학생이 세션과 단일 요청의 차이를 설명하게 한다.
- hidden token, input name, 쿠키 key를 구분하게 한다.
- DemoSession으로 로그인, 필터, 장바구니 상태를 안전하게 관찰하게 한다.
- session_events.csv를 재생해 상태 변화 순서를 이해하게 한다.
- 민감정보를 저장하지 않는 로그와 요약 산출물을 만들게 한다.

## 2시간 운영 흐름

| 시간 | 운영 | 확인 포인트 |
|---:|---|---|
| 0-15분 | 세션 개념과 안전 기준 | 실제 쿠키 사용 금지, fixture만 사용 |
| 15-35분 | 로그인 폼 구조 읽기 | h1, hidden token, input name |
| 35-60분 | DemoSession 로그인과 쿠키 | is_logged_in, cookies, log |
| 60-85분 | 카탈로그 필터와 장바구니 | data-category, data-price, cart_count |
| 85-105분 | 이벤트 CSV 재생 | add/remove 순서와 replay 상태 |
| 105-120분 | 산출물 리뷰 | session_log.csv, session_summary.json |

## 수업 전 준비

- 코랩 버튼이 Kevin-innovation/jupyter-lecture의 lesson 05 노트북을 여는지 확인한다.
- login_form.html, catalog_page.html, cookie_policy.txt, session_events.csv를 먼저 열어 구조를 확인한다.
- 학생에게 실제 계정, 실제 쿠키, 비밀번호를 사용하지 않는 수업이라고 명확히 안내한다.
- outputs/lesson05 산출물은 수업 후 삭제해도 되는 합성 결과임을 안내한다.

## 핵심 질문

1. 세션 객체를 새로 만들면 어떤 상태가 사라지는가?
2. hidden token은 왜 화면에는 보이지 않지만 코드에서는 읽히는가?
3. 쿠키 key와 쿠키 value 중 산출물에 남겨도 되는 것은 무엇인가?
4. 장바구니에는 상품명과 가격을 모두 저장해야 하는가?
5. 이벤트 로그를 순서대로 재생하지 않으면 어떤 결과가 달라지는가?

## 피드백 문장 예시

- token을 잘 읽었다. 다만 실제 서비스 token은 저장하거나 제출하지 않는다는 기준을 함께 적어야 한다.
- session 객체를 다시 만들어 이전 쿠키가 사라졌다. 같은 상태를 이어가야 하는 구간에서는 같은 객체를 써야 한다.
- data-price를 숫자로 바꿔 총액 계산으로 연결한 점이 좋다.
- 이벤트 재생에서 remove가 빠져 최종 cart_count가 실제 로그와 맞지 않는다.
- JSON 요약에 cookie value가 들어갔다. cookie_keys만 남기는 방식으로 수정해야 한다.

## 수업 후 점검

수업 후에는 outputs/lesson05/session_log.csv와 session_summary.json을 먼저 확인한다. CSV에는 event 행이 있어야 하고, JSON에는 cookie_keys는 있어도 session_id 원문 값은 없어야 한다. 학생이 상태 추적과 민감정보 저장 금지를 함께 이해했는지 확인하는 것이 이 레슨의 핵심이다.

## 운영형 평가 기준

5강은 보안과 상태 추적이 함께 들어가므로 결과만 맞히는 평가가 위험하다. 학생이 실제 쿠키를 쓰지 않았는지, token과 session_id를 산출물에 저장하지 않았는지, 상태 변화 순서를 설명할 수 있는지 함께 확인해야 한다.

수업 중에는 "쿠키를 볼 수 있다"와 "쿠키를 저장해도 된다"를 분리해서 설명한다. 합성 fixture에서는 쿠키 값이 안전하지만 실제 서비스에서는 민감정보일 수 있다. 따라서 산출물에는 cookie_keys와 개수처럼 구조 요약만 남기는 습관을 만든다.

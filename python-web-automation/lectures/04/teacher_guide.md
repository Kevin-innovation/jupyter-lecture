# 레슨 04 — 교사 가이드

## 수업 목표

- 학생이 다운로드 대상의 텍스트, href, data 속성을 구분하게 한다.
- 파일 저장을 bytes 기준으로 처리하게 한다.
- 안전한 파일명과 저장 폴더 기준을 설명하게 한다.
- manifest 기준으로 저장 로그를 만들게 한다.
- 저장 결과를 파일 크기와 로그 행 수로 검증하게 한다.

## 2시간 운영 흐름

| 시간 | 운영 | 확인 포인트 |
|---:|---|---|
| 0-15분 | 자료실 fixture 확인 | a.file-link, href, data 속성 구분 |
| 15-35분 | 환경 셀과 단일 파일 저장 | DATA_BASE, load_bytes, write_bytes 확인 |
| 35-60분 | manifest 읽기 | file_name, group, type, path 구분 |
| 60-85분 | 그룹별 폴더 저장 | 폴더 생성과 파일 크기 확인 |
| 85-105분 | 로그 CSV/JSON 저장 | header, 행 수, summary 확인 |
| 105-120분 | 최종 미션 리뷰 | 재실행 가능성과 안전 메모 확인 |

## 수업 전 준비

- 코랩 버튼이 Kevin-innovation/jupyter-lecture의 lesson 04 노트북을 여는지 확인한다.
- data/resource_center.html과 manifest.csv를 먼저 열어 링크 수와 manifest 행 수를 확인한다.
- data/files 폴더의 샘플 파일들이 존재하는지 확인한다.
- 실제 사이트를 요청하지 않고 fixture만 사용하는 수업이라고 안내한다.

## 핵심 질문

1. 화면에 보이는 파일명과 href 경로는 같은가?
2. 파일 저장에 load_text가 아니라 load_bytes를 쓰는 이유는 무엇인가?
3. 저장 폴더 기준을 group, week, type 중 무엇으로 잡을 것인가?
4. 저장된 파일이 정상인지 어떤 값으로 검증할 것인가?
5. 다음 실행 때 중복 다운로드를 어떻게 피할 것인가?

## 채점 기준

| 항목 | 기준 |
|---|---|
| 대상 식별 | HTML 링크와 manifest 경로를 정확히 읽는다 |
| 경로 처리 | 코랩과 로컬에서 모두 동작하는 경로를 만든다 |
| 저장 구조 | 폴더를 만들고 bytes로 파일을 저장한다 |
| 검증 | size, 행 수, 상태 값을 확인한다 |
| 산출물 | CSV 로그와 JSON 요약을 만든다 |
| 안전 메모 | 최대 파일 수, 요청 간격, 저장 권한을 언급한다 |

## 문제별 지도 흐름

| 구간 | 지도 초점 | 추가 질문 |
|---|---|---|
| 문제 1~3 | 링크 구조 읽기 | 텍스트와 href 중 실제 다운로드 경로는 무엇인가? |
| 문제 4~6 | 경로와 목록 기준 | HTML 링크와 manifest 중 무엇을 기준으로 저장할까? |
| 문제 7~10 | 저장 함수 | 폴더가 없을 때 코드는 어떻게 처리하는가? |
| 문제 11~15 | 검증과 로그 | 저장 파일이 비어 있지 않다는 증거는 무엇인가? |

## 피드백 문장 예시

- 링크 개수 확인은 좋다. 다음에는 manifest 행 수와 비교해 누락 여부도 확인하자.
- 저장 함수가 Path를 반환해서 이후 로그 생성으로 연결하기 좋다.
- 파일 크기 검증이 빠져 있어 빈 파일을 성공으로 오해할 수 있다.
- CSV 로그에 header가 있어 검수하기 쉽다. source_path도 함께 남기면 더 좋다.
- 실제 사이트 확장 전 최대 파일 수와 저장 권한을 명시하면 운영 기준이 더 분명해진다.

## 다음 레슨 연결

5강에서는 수집 데이터 검증과 오류 처리가 더 중요해진다. 4강에서 저장 로그를 남기는 습관을 만들어 두면, 이후 실패한 항목만 재시도하거나 오류 메시지를 분류하는 수업으로 자연스럽게 이어진다.

## 수업 후 점검

수업 후 학생 산출물에서 먼저 볼 것은 코드 모양이 아니라 downloads/lesson04 폴더 구조다. group 기준을 선택했다면 plan, score, ops 같은 폴더가 생겨야 한다. week 기준을 선택했다면 week_1, week_2처럼 폴더가 나뉘어야 한다. 폴더 구조가 설명한 기준과 다르면 코드가 우연히 실행되었더라도 보완이 필요하다.

다음으로 download_log.csv를 열어 행 수와 size를 확인한다. manifest 행 수와 로그 행 수가 다르면 누락이 있다. size가 0인 행이 있으면 실패 처리가 필요하다. 마지막으로 download_summary.json에 전체 개수, empty 파일 수, type별 개수가 들어 있는지 확인한다.

## 운영형 평가 기준

4강은 코드가 짧아 보여도 운영 품질 차이가 크게 난다. 단순히 파일을 저장한 학생과, 저장 기준·검증·로그를 갖춘 학생을 구분해서 피드백해야 한다. 수업 중에는 파일을 받는 속도보다 저장 후 확인 절차를 더 강조한다.

수업 종료 전에는 세 가지를 확인한다. 첫째, 학생이 manifest의 path와 file_name 차이를 설명할 수 있는가. 둘째, 저장된 파일 크기를 확인하는 코드를 작성했는가. 셋째, CSV 로그를 다시 읽어 행 수를 검증했는가. 이 세 가지가 되면 다음 레슨의 오류 처리와 재시도 로직으로 넘어갈 준비가 된 것이다.

- 실제 사이트에서 요청 간격을 두지 않으면 어떤 문제가 생길 수 있는가?

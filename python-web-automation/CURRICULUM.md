# 파이썬 웹 자동화 커리큘럼

> 코드명: `python-web-automation`
> 총 길이: 10레슨 × 2시간 = 20시간
> 형식: 코랩 / Jupyter / VSCode 노트북 (`.ipynb`)
> 채점: 우리 사이트 IDE에서 자동 채점하지 않음. 교사가 노트북 결과 + 최종 미션 산출물로 평가.
> 원칙: 합법적이고 안정적인 자동화만 다룬다. 로그인 우회, 유료 데이터 무단 수집, 과도한 요청, 개인정보 수집은 수업 범위에서 제외한다.

## 코스 목표

이 코스를 마친 학생은 다음을 할 수 있다.

1. 웹 자동화와 크롤링의 차이를 설명하고 안전 규칙을 적용한다.
2. HTTP 요청/응답, status code, timeout, User-Agent를 이해하고 코드에 반영한다.
3. HTML 구조에서 반복 단위를 찾고 BeautifulSoup selector로 필요한 값을 추출한다.
4. URL, query string, pagination, relative URL을 다루어 여러 페이지 데이터를 정리한다.
5. Selenium/Playwright 같은 브라우저 자동화가 필요한 상황과 필요하지 않은 상황을 구분한다.
6. 수집 결과를 CSV/JSON으로 저장하고, 누락·중복·형식 오류를 검증한다.
7. 요청 간격, 재시도, 로그를 포함한 작은 운영형 자동화 스크립트를 만든다.

## 선수 지식

- 파이썬 기초 (`python-basics-kor-eng`) 수료 또는 동급.
- 변수, 리스트, 딕셔너리, 반복문, 조건문, 함수에 익숙해야 한다.
- HTML 기초: 태그, 속성, class, id, 링크 구조를 읽을 수 있어야 한다.
- CSV 저장 경험이 있으면 좋지만 필수는 아니다.

## 운영 환경

- **기본**: Google Colab (별도 설치 없이 브라우저에서 실행).
- **대안**: 로컬 VSCode + Jupyter 확장. 학생이 선호하면 가능.
- 우리 사이트 IDE는 이 코스의 실행 환경이 아니다. 사이트에는 강의 문서와 미션 안내만 노출되고, 실행은 외부 환경에서 한다.
- 실제 외부 사이트 요청은 후반부에서 제한적으로만 다룬다. 1~5강은 합성 HTML/CSV fixture를 우선 사용한다.

| 03 | HTML 테이블과 리스트 정리 | `BeautifulSoup`, `csv` | table/card/list 혼합 HTML | 자료실 목록, 대시보드 표 추출 | 표/카드형 데이터 통합 |

## 각 레슨 산출물(고정)

레슨마다 다음 파일이 있어야 한다. **각 파일은 정해진 용량 범위 안에 들어와야 한다** (자세한 검증 명령은 `AUTHORING_GUIDE.md` §8 참조).

| 파일 | 역할 | 최소 | 최대 |
|---|---|---:|---:|
| `lecture.md` | 개념 + 안전 규칙 + 현업 사례 + 예제 코드 | **18 KB** | **24 KB** |
| `mission.md` | 실습 문제 15~20개 + 힌트 + 통과 기준 | 14 KB | 24 KB |
| `solution.md` | 문제별 정답 + 상세 설명 (학생 비공개) | 24 KB | 42 KB |
| `final-mission.md` | 레슨 통합 프로젝트 | 5 KB | 8 KB |
| `final-mission-solution.md` | 최종 미션 모범 답안 | 5 KB | 9 KB |
| `teacher_guide.md` | 레슨용 교사 가이드 (8개 절) | 5 KB | 9 KB |
| `data/README.md` | fixture 설명 | 1 KB | 4 KB |

fixture 최소 기준:

| 파일 유형 | 최소 기준 |
|---|---:|
| 반복 카드 HTML | 8개 item |
| 공지/게시판 HTML | 10개 item |
| CSV target 목록 | 10행 |
| robots/sample policy | 5개 규칙 |

```
lectures/<NN>/
├── [학생용] 레슨 NN — 제목.ipynb  # 앱 Colab 버튼용 학생 통합 노트북
├── 레슨 NN — 제목.ipynb          # 앱 Colab 버튼용 선생님 통합 노트북
├── lecture.md                    # 개념 + 현업 사례 + 예제 코드 (마크다운 원본)
├── lecture.ipynb                 # lecture.md를 jupytext로 변환
├── mission.md                    # 실습 문제 15~20개 (마크다운 원본)
├── mission.ipynb                 # 학생이 채워 넣을 빈 노트북
├── solution.md / .ipynb          # 문제별 정답과 상세 설명 (학생 비공개)
├── final-mission.md / .ipynb     # 레슨 최종 프로젝트 스타터
├── final-mission-solution.md / .ipynb  # 최종 미션 모범 답안
├── teacher_guide.md              # 이 레슨용 교사 가이드
└── data/                         # 이 레슨에서만 쓰는 HTML/CSV/TXT fixture
```

`.md` 가 원본이고 `.ipynb` 는 변환물이다. 변환 방법과 검증 명령은 `AUTHORING_GUIDE.md` 를 따른다.

## 평가 가이드라인

- 레슨 단위 평가: 미션 노트북 15~20문제 중 **75% 이상 통과** + 최종 미션 제출 완료. 15문제 기준 12문제 이상 통과를 기본 완료 기준으로 본다.
- 코스 단위 평가: 10번 통합 프로젝트의 자동화 노트북 + CSV/JSON 산출물 + 3문장 운영 메모.
- 자동 채점이 없는 코스이므로 교사가 "레슨 완료" 상태를 수동 트리거한다.
- 정답 출력만 보지 않는다. timeout, 오류 처리, selector 안정성, 요청 간격 설명이 함께 보여야 한다.

## 콘텐츠 작성 원칙

- 한 레슨에서 새로 다루는 함수·메서드는 7개 이내로 제한한다. 그 이상이면 다음 레슨으로 미룬다.
- 예제 코드는 항상 fixture 데이터로 재현 가능해야 한다.
- "실제 사이트를 긁어 보자"가 아니라 "같은 구조를 안전하게 해석하자"로 설명한다.
- 현업·운영 활용 섹션은 최소 1개 이상의 구체 사례(업무 자동화, QA, 공지 모니터링, 공개 데이터 점검 등)를 포함한다.
- 최종 미션은 항상 결과물을 누군가에게 보여줄 수 있는 형태로 끝나야 한다(CSV, 표, 짧은 글, 로그 요약).
- 학생 힌트는 정답 코드의 대부분을 노출하지 않는다. `____` 빈칸 scaffold와 조건 방향만 준다.

## 라이선스 / 데이터 출처

- 모든 실습 데이터는 합성(synthetic) 또는 공개 라이선스 데이터만 사용한다.
- 데이터 출처는 각 레슨 `lecture.md` 하단 "데이터 출처와 안전 규칙" 절에 명시한다.
- 실명/개인정보가 들어간 데이터는 사용하지 않는다.
- 외부 사이트 예시는 약관과 robots.txt 확인을 전제로 하며, 수업 중 대량 요청을 보내지 않는다.
